Security incident report


Section 1: Identify the network protocol involved in the incident
	Protocols: The tcpdump capture shows DNS, TCP, and HTTP. DNS translates domain names to IP addresses; TCP establishes connections through the SYN, SYN-ACK, ACK three-way handshake; HTTP requests website content over TCP port 80.
Traffic evidence: At 14:18:32, dns.google resolves yummyrecipesforme.com to 203.0.113.22. At 14:18:36, the browser completes a TCP handshake and sends HTTP GET /. At 14:20:32, dns.google resolves greatrecipesforme.com to 192.0.2.17. At 14:25:29, the browser completes another TCP handshake and sends HTTP GET / to that second site.
	

Section 2: Document the incident
	Incident and initial access: A former employee carried out a brute-force password-guessing attack against the website administrator account. The password was still a known default value, and no controls prevented repeated login attempts. After gaining access, the attacker changed the website source code to insert JavaScript that urged visitors to download a supposed browser update. The attacker then changed the administrator password, locking out the owner.
Detection: Several hours later, customers reported an unexpected download prompt, redirection to another website after running the file, and slower computers. The website owner could not sign in to the admin panel and contacted the hosting provider.
Investigation and timeline: Analysts reproduced the behavior in a sandbox and captured network traffic using tcpdump. The browser visited yummyrecipesforme.com (DNS response 14:18:32; HTTP request 14:18:36), then resolved greatrecipesforme.com (14:20:32) and requested its webpage over HTTP (14:25:29). A senior analyst identified the injected JavaScript, and file analysis found a script that redirects the browser to the fake site.
Impact and evidence limits: The website was modified without authorization, administrative access was lost, and visitors were exposed to a malicious executable and fraudulent website. The log supports the DNS/TCP/HTTP connection sequence but does not itself display password guesses, injected code, or malware behavior. Reported customer slowdown does not prove data theft. The date and exact time of the initial compromise are not provided.
Immediate response: Preserve relevant logs and the modified source code, work with the hosting provider to regain secure administrative access, remove the injected code and malicious download, restore verified-clean website files, and warn affected customers not to run the fake update.
	

Section 3: Recommend one remediation for brute force attacks
	Recommended preventive control: Require multi-factor authentication (MFA) for every administrative login, preferably using a phishing-resistant authenticator or security key. Even if an attacker guesses the correct password through brute force, the password alone will not grant access to the admin panel. During incident recovery, the compromised administrator password should also be replaced with a strong, unique, non-default password.
